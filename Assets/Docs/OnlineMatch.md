# 온라인 한 판의 기본 흐름

`WaitingRoomScene`에서 준비한 참가자들이 `GameScene`으로 이동한 뒤 서버 전용 `HostedMatch`와 기존 `MatchSession`을 시작한다. 씬 분리와 연결 수명은 [SceneFlow.md](SceneFlow.md)를 참고한다. 기존 `MultiplayerBase`는 개발용으로 보존한다.

## 게임 시작과 개인 정보

- 방장이 게임 시작을 누르면 서버가 4~12명의 준비된 참가자와 소유권을 확인한다. 해당 참가자 전원의 게임 씬 로딩을 확인한 뒤 판을 시작한다.
- 서버만 시드를 생성하고 번호 1~N을 중복 없이 배정한다. 원조 마피아는 항상 1명이다.
- 자기 번호는 본인에게도 숨긴다. 개인 진영과 원조 마피아 여부는 해당 캐릭터 소유자에게만 `TargetRpc`로 보낸다.
- 개인 정보는 `NetworkPlayer`의 일반 로컬 필드에 보관한다. 전체 진영표, 실제 번호, 시드, `MatchSession`은 SyncVar/RPC 공개 상태에 넣지 않는다.
- 공개 상태는 판 식별자, 참가자 수, 진행 단계, 경과/남은 시간, 팀 포인트, 공개 적용 규칙이다. 판의 결과가 확정된 뒤에만 번호와 진영을 결과 화면에 공개한다.

## 시간과 제출

서버의 경과 시간으로 Core를 진행한다. 18분에 정보 수집 종료/최종 토론, 20분에 30초 최종 제출, 전원 제출 또는 마감 시 결과 판정이다. 5/10/15분 규칙 적용과 90초마다 최소 팀 포인트 지급도 기존 Core를 따른다. 공개 상태는 최대 5Hz로 확인하고 변경된 SyncVar만 복제한다.

게임 HUD는 자기 진영, 숨겨진 자기 번호 안내, 시간, 팀 포인트, 활동 단계, 적용 규칙을 표시한다. 제출 단계에서 최종 번호와 선택적인 의심 대상(기권 가능)을 선택하고 답안을 확정한다. 한 번 확정하면 변경할 수 없다. 개인 제출 여부와 응답은 소유자에게만 전달한다.

제출 요청의 플레이어 ID는 요청 인수가 아니라 PurrNet이 인증한 캐릭터 소유자에서 구한다. 서버는 판 식별자, 참가자, 제출 단계, 범위, 중복 제출, 자기 자신/잘못된 의심 대상을 다시 검증한다. 이전 판의 지연 요청은 거부한다. 클라이언트가 번호 배정이나 서버 시간을 설정하는 RPC는 없다.

## 종료와 이탈

결과 화면은 시민 정답 수, 필요한 정답 수, 의심 보너스, 승리 진영과 참가자별 번호/제출/진영을 표시한다. 방장은 언제든 대기실로 돌아가 판을 끝낼 수 있다. 이때 개인 진영 캐시, 제출 상태, 공개 결과, 시계와 준비 상태를 초기화하고 새 판 식별자를 사용한다.

현재는 진행 중 참가자 한 명이 나가면 판을 중단하고 남은 사람을 대기실로 돌려보낸다. 중단 시 비밀 번호나 진영을 공개하지 않는다. 결과가 이미 확정된 뒤 참가자가 나가면 남은 사람은 결과를 계속 볼 수 있다. 방장 이탈은 기존 방 종료 정책을 따른다. 진행 중 재접속/자리 보존 정책은 후속 설계 대상이다.

## 아직 연결하지 않은 플레이

홀짝 검사 장치의 E키 사용, 서버 거리·포인트·쿨다운·동행 검증과 개인 단서 노트를 연결했다. 공개 홀짝 규칙과 번호 교환 후 과거 단서 표시도 포함한다. 상세 범위는 [InformationDevices.md](InformationDevices.md)를 참고한다. 다른 정보 장치, 온라인 포섭과 협동 미션은 후속 작업이다.

## 검증

사용자의 지시에 따라 이 작업에서는 에디터 Play 모드와 PlayMode 테스트를 실행하지 않는다. 순수 C# EditMode 테스트에서 비밀 정보 공개 시점, 참가자/판 검증, 시간 경계, 제출 불변성, 이탈 중단과 새 판 초기화를 확인한다. UI 배치는 Play 없이 별도 PreviewScene에서 버튼 영역과 드롭다운 템플릿을 확인한다.

실제 여러 Steam 계정/클라이언트 사이의 TargetRpc 전달, 상태 동기화와 결과 전송은 실환경 검증이 남아 있다. 패키지 변경 전에는 매번 사용자 승인을 받는다.

2026-10-09, Unity 6000.3.22f1 배치 EditMode 검증: **73개 통과, 실패/건너뛰기 0개**. 기존 Core/로비 63개와 새 판의 권한·수명 9개, Play 진입 없는 HUD 배치 1개를 포함한다. 보고서는 로컬 `Logs/online-match-editmode.xml`에 저장한다. PurrNet 코드 생성까지 컴파일했다. 패키지 manifest/lock 해시는 작업 전후 동일하다.
