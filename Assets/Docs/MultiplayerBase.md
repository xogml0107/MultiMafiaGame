# 멀티플레이 로비

`Assets/Scenes/MultiplayerBase.unity`에 국가별 Steam 방 목록과 PurrNet 대기실을 연결했다. 국가 선택은 Steam 로비 메타데이터를 필터링한다. 국가별 전용 서버나 위치 보장 기능은 아니다.

## 실행과 입장

1. Unity 6000.3.22f1에서 씬을 연다. 필요한 컴포넌트와 글꼴을 연결하는 메뉴는 `ZZabmongus > Configure Country Room Lobby`이다.
2. 사용자가 Play를 실행하면 대한민국/일본/싱가포르/미국/독일/호주 중 국가를 선택한다. Steam 실행과 유효한 App ID 설정이 필요하다. 이름 입력, 새로고침, 방 생성 버튼이 있다.
3. 방 생성에서 이름과 최대 인원(4~12명)을 설정한다. `공개 방` 체크를 끄면 비밀번호 입력이 활성화된다. 공개로 바꾸면 비밀번호를 지운다.
4. 공개 방은 더블 클릭하면 바로 입장을 시도한다. 비공개 방은 잠금 아이콘을 표시하고 더블 클릭하면 비밀번호 입력창을 연다. 호스트가 올바른 비밀번호를 확인해야 캐릭터를 생성한다.
5. 정원이 찬 방은 공개 여부와 관계없이 `방 인원이 가득 찼습니다.` 팝업으로 입장을 막는다. 목록 확인 이후 다른 참가자가 먼저 들어온 경우에도 호스트가 정원을 다시 확인한다.
6. 입장 후 WASD/방향키로 이동하고 색상과 준비 상태를 설정한다. 4명 이상 모두 준비하면 호스트가 게임을 시작한다. `대기실로 돌아가기`는 준비 상태를 초기화한다. 방장 이탈 시 방을 종료한다.

목록은 기본적으로 5초마다 갱신한다. 최초 Steam 초기화 실패 시 자동 재시도를 멈추고, 새로고침이나 방 생성 버튼으로 다시 시도할 수 있다. 검색은 선택 국가에 맞는 게임/프로토콜/준비된 방만 최대 100개 표시한다. 진행 중인 방에는 입장할 수 없다.

## Steam 목록과 실제 정원

Steam 검색은 Steam 자체 정원이 꽉 찬 방을 반환하지 않는다. 따라서 검색용 Steam 로비의 정원은 250으로 두고 게임 정원은 별도의 4~12명 값으로 관리한다. 덕분에 게임 정원이 찬 방도 목록에 남아 인원과 정원 초과 팝업을 표시할 수 있다. 검색 가능 여부와 거리 필터의 동작은 [Steam ISteamMatchmaking 문서](https://partner.steamgames.com/doc/api/ISteamMatchmaking?l=english)를 따른다.

비공개 게임도 목록에 보여야 하므로 검색용 Steam 로비 타입은 Public이다. 비밀번호를 입력한 참가자는 검색용 Steam 로비에 먼저 들어간 뒤 PurrNet 인증을 받는다. 이 단계는 게임 입장 승인이 아니며 인증에 실패하면 검색용 로비에서도 나간다.

공개 메타데이터에는 방 이름, 국가, 잠금 여부, 호스트 Steam ID, 포트, 정원, 인증된 인원, 진행 상태만 저장한다. 비밀번호·해시·salt는 Steam 메타데이터에 저장하지 않는다. 호스트는 salt를 사용하는 PBKDF2 SHA256 해시로 비밀번호를 확인하고 인증과 좌석 예약을 함께 처리한다. 연결 종료 시 좌석을 반환한다. 인증 성공 전에 플레이어 소유권이나 게임 상태를 제공하지 않는다.

## 기존 멀티 베이스

- PurrNet이 캐릭터 생성, 소유권, 서버 이동, 벽 충돌과 공개 대기실 상태를 관리한다.
- 입력은 소유자만 보내고 서버가 길이를 제한한다. 오래된 입력은 무시하며 0.25초 동안 입력이 없으면 멈춘다. 입력 20Hz, 네트워크 틱 30Hz이다.
- `게임 시작`은 대기실/세션 상태를 전환한다. Core의 번호 배정, 비밀 진영, 정보 장치, 미션, 채점은 아직 네트워크에 연결하지 않았다.
- UI와 플레이어 이름은 Noto Sans KR 정적 글꼴과 동적 fallback을 사용한다. 원본 글꼴과 OFL 라이선스는 `Assets/Art/Fonts/`에 포함한다.

LAN 개발 연결은 `RoomBrowserHud`를 비활성화하면 기존 IP/포트 UI로 사용할 수 있다. UDP에는 인터넷 NAT 우회 기능이 없다. `ZZabmongus > Build Multiplayer Windows Test Player`는 이 씬의 Development 빌드를 `Build/MultiplayerBase/ZZabmongus.exe`로 만든다.

## 검증과 작업 정책

2026-10-09 검증:

- EditMode 63개 통과: 기존 Core 46개 + 방 목록/입장/비밀번호/정원 17개.
- 사용자 테스트 제한 지시 이전 PlayMode 3개 실행: 기존 멀티 호스트/이동/나가기/재생성 및 샌드박스 2개 통과. 로비 UI 1개는 테스트용 디렉터리 교체 후 버튼이 기존 컨트롤러를 참조해서 실패했다. 현재 컨트롤러를 참조하도록 수정했으나 PlayMode 재실행은 하지 않았다.
- 저장된 화면에서 한글 방 목록, 잠금 아이콘, 정원 초과 팝업 표시를 확인했다. 화면은 로컬 `Logs/room-browser-main.png`, `Logs/room-browser-full.png`에 있다.
- 서로 다른 Steam 계정 간 실제 검색/생성/입장과 동시 정원 경쟁은 아직 실환경에서 검증하지 않았다.

**사용자가 별도로 지시하지 않으면 에디터 Play 모드가 필요한 테스트를 실행하지 않는다.** 패키지 추가·업데이트·재설치·제거도 매번 먼저 사용자 승인을 받는다. 이번 로비 작업은 기존 PurrNet/Steamworks.NET을 사용하며 패키지 파일을 변경하지 않는다.

Development 빌드의 `-zzNetProbe host|1|2|3 -zzNetPort 15000 -zzNetResult <절대 JSON 경로>`는 선택적인 네 프로세스 UDP 테스트 기능이다. 일반 실행에서는 비활성이다. 이번 작업에서 실행하지 않았다.
