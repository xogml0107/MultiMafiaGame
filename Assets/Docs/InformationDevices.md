# 온라인 홀짝 검사와 개인 단서 노트

`GameScene`에 홀짝 검사 장치 1개를 배치한다. 장치 위치는 기본 맵의 `(0, 0, 5)`이고 `ParityInformationDevice.prefab`을 사용한다. 메뉴 `ZZabmongus > Configure Game Information Device`는 기존 장치가 없을 때만 추가하며, 이미 배치한 장치와 다른 맵 오브젝트를 덮어쓰지 않는다.

## 사용과 규칙

- **E**: 가까운 정보 장치 사용. **F 길게 누르기**는 기존 포섭 키로 보존한다. 온라인 포섭은 아직 연결하지 않았다.
- 상호작용 거리는 2.5m이다. 장치 사용은 정보 수집 단계에서만 가능하고, 씬 로딩·최종 토론·제출·결과 단계에서는 닫힌다.
- 홀짝 검사는 팀 포인트 **1점**을 소비하고, 사용자에게 **30초**의 재사용 대기시간을 적용한다. 같은 사람이 다른 장치로 옮겨도 이 대기시간을 공유한다.
- 시작 포인트와 미션 보상은 기존 Core 규칙을 유지한다. 현재 온라인 미션은 아직 연결하지 않았으므로 **90초마다 +1점**인 최소 지급으로 첫 검사를 할 수 있다.
- 기본 결과는 해당 플레이어의 노트에만 기록한다. 실제 자기 번호는 전달하지 않는다.
- ‘홀짝 결과 공개’ 규칙이 적용되면 해당 홀짝 관측만 모두의 노트에 `[공개]`로 기록한다. 각 사용자의 기존 개인 단서나 진영은 공유하지 않는다.
- ‘정보 장치 2인 동행’ 규칙은 서버가 참가자 위치로 확인한다. 사용자의 근처이면서 같은 장치의 범위 안인 다른 참가자가 필요하다.

## 서버 요청과 개인 전송

클라이언트의 소유권이 확인된 캐릭터에서 `RequestInspect(판 ID, 장치 ID)`를 요청한다. 플레이어 ID, 장치 종류·좌표, 가격, 지급량, 번호를 클라이언트 요청으로 받지 않는다. 서버는 등록한 맵 장치와 권위 캐릭터 좌표를 사용한다. 수직 거리와 벽 등 장애물도 확인한다. 요청 빈도는 사용자당 최소 0.25초로 제한한다.

`HostedMatch.TryInspect`가 판·참가자·장치·서버 위치·거리와 Core의 단계·포인트·쿨다운·동행 규칙을 검증한다. 실패한 요청은 포인트를 소비하거나 단서를 만들지 않는다.

노트는 `TargetRpc`로 각 소유자에게 **자신의 PlayerView에 포함된 단서만** 전송한다. 전송 형태는 결과 문장, 관측 시각, 관측 당시 번호 epoch, 공개 여부이다. 실제 번호·시드·전체 진영표를 전송하지 않는다. 일반 로컬 캐시에 보관하며 SyncVar로 저장하지 않는다.

HUD 오른쪽의 개인 단서 노트에 시각과 공개/개인 표시를 남긴다. 긴 기록은 스크롤할 수 있다. 번호 교환 시 서버가 새 epoch를 전달하면 이전 관측을 `[과거]`로 표시한다. 새 판, 대기실 복귀와 연결 종료 시 개인 캐시와 쿨다운 표시를 초기화한다. 이전 판의 지연 응답은 판 ID로 거른다.

## 검증과 후속 작업

패키지를 변경하지 않는다. Play 모드와 PlayMode 테스트를 실행하지 않는다. 순수 C# EditMode에서 권한·거리 경계·가격·쿨다운·공개/동행 규칙·번호 교환·판 초기화를 검증하고, PreviewScene에서 장치 배치와 스크롤 영역을 확인한다.

2026-10-11, Unity 6000.3.22f1에서 `ZZabmongus.Tests` EditMode **96개가 모두 통과**했다. 기존 86개에 장치 권위 검증 9개와 씬/프리팹 검증 1개를 추가했고, 기존 HUD 레이아웃 검증에는 개인 노트의 스크롤 영역을 포함했다. 테스트 보고서는 `Logs/information-device-editmode.xml`에 기록했다. 장치 생성과 PurrNet RPC 코드는 컴파일을 통과했다.

실제 E키 입력에서 여러 클라이언트로 이어지는 RPC 전달과 벽 충돌 검증은 사용자 별도 실행 지시 이후의 실환경 검증 대상이다. 다른 정보 장치, 온라인 포섭, 협동 미션은 다음 단계이다. 네트워크 요청/응답이 추가되어 Steam 방 검색과 인증 프로토콜은 **4**를 사용한다.
